# BackPack+

**فِیل‌اوور خودکار بین دو (یا چند) سرور ایران برای تانل‌های [BackPack](https://github.com/AminMGMT/BackPack)**

BackPack+ روی **سرور خارج** اجرا می‌شود و همهٔ تانل‌های هر دو سرور ایران را مدام چک می‌کند. اگر **سرور مبنا** قطع شد یا مدام قطع و وصل شد، رکورد دامین را در **آروان** به سرور دیگر عوض می‌کند. وقتی سرور مبنا دوباره وصل شد و **۱۰ دقیقه بدون قطعی** ماند، رکورد را برمی‌گرداند. همهٔ این کارها را در **ربات تلگرام** گزارش می‌دهد.

```text
                         کاربران
                            │  tun.example.com  (رکورد A در آروان)
                            ▼
          ┌─────────────────┴─────────────────┐
          ▼  (مبنا)                            ▼  (رزرو، ولی وصل)
   ┌─────────────┐                      ┌─────────────┐
   │  Iran 1     │                      │  Iran 2     │
   │  BackPack   │                      │  BackPack   │
   │  main/panel │                      │  main/panel │
   └──────▲──────┘                      └──────▲──────┘
          │ TCP Mux (چند تانل)                 │ TCP Mux (چند تانل)
          │         ┌───────────────────┐      │
          └─────────┤  Kharej           ├──────┘
                    │  BackPack         │
                    │  BackPack+  ──────┼──► Arvan API (تغییر رکورد)
                    │                   ├──► Telegram (گزارش و دستور)
                    └───────────────────┘
```

## چطور کار می‌کند

- **همهٔ تانل‌ها همیشه وصل‌اند.** جابه‌جایی فقط عوض کردن رکورد دامین است. به محض اینکه دامین به ایران ۲ اشاره کند، ترافیک خودبه‌خود از تانل‌های ایران ۲ می‌رود.
- **سرور مبنا** سروری است که دامین در حالت عادی روی آن است. در ویزارد نصب انتخابش می‌کنی، در کانفیگ `"primary"` است، و از ربات هم با `/primary iran2` عوض می‌شود.
- **هر سرور می‌تواند چند تانل داشته باشد** (مثلاً ۵ تا). هر تانل یک «پورت چک» جدا دارد و همه جداگانه چک می‌شوند. به‌طور پیش‌فرض اگر **حتی یکی** از تانل‌های یک سرور قطع شود، آن سرور ناسالم حساب می‌شود و پیام دقیقاً می‌گوید کدام تانل قطع است. دلیلش این است که کاربرانِ آن تانل هم کاربرند، و سرور دیگر همهٔ تانل‌ها را سالم دارد. با `"require_all_tunnels": false` سرور فقط وقتی ناسالم است که **همهٔ** تانل‌هایش قطع باشند.
- **چک واقعی و سرتاسری.** BackPack+ هر ۱۰ ثانیه به پورت چکِ هر تانل روی سرور ایران وصل می‌شود. BackPack ایران آن اتصال را **از داخل همان تانل** به سرور خارج برمی‌گرداند (`127.0.0.1:59998`)، جایی که BackPack+ یک echo کوچک دارد و یک توکن تصادفی را پس می‌فرستد. اگر توکن برگشت یعنی سرور ایران در دسترس است، BackPack ایران بالاست و همان تانل وصل است و داده رد می‌کند. اگر تانل قطع باشد توکن برنمی‌گردد.
- **وضعیت هر سرور:**
  - 🟢 **سالم**: ۳ چک موفق پشت سر هم
  - 🔴 **قطع**: ۳ چک ناموفق پشت سر هم
  - 🟠 **ناپایدار**: ۳ بار قطع شدن در ۵ دقیقهٔ اخیر، حتی اگر هر قطعی کوتاه باشد
- **فِیل‌اوور:** اگر سرور فعال قطع یا ناپایدار شد و سرور دیگری سالم بود، رکورد عوض می‌شود.
  - اگر هیچ سرور سالمی نباشد رکورد دست نمی‌خورد و فقط هشدار می‌دهد.
  - اگر سرور فعال کاملاً قطع باشد و سرور دیگر ناپایدار ولی در حال جواب دادن، به همان ناپایدار می‌رود.
- **تأیید انتشار DNS:** بعد از تغییر رکورد، DNSهای عمومی را مدام می‌پرسد و وقتی همه آی‌پی جدید را دادند پیام می‌دهد. اگر رکورد پشت CDN آروان باشد، تغییر فوری است.
- **برگشت به سرور مبنا:** بعد از **۱۰ دقیقهٔ کامل بدون حتی یک قطعی**. هر قطعی کوچک این شمارش را از صفر شروع می‌کند.
- **ضد نوسان:** بعد از هر جابه‌جایی، حداقل ۳ دقیقه هیچ جابه‌جایی غیراضطراری انجام نمی‌شود. اگر سرور فعال کاملاً قطع شود، فوراً جابه‌جا می‌کند.
- **تغییر دستی رکورد** از پنل آروان شناسایی می‌شود و مبنا قرار می‌گیرد.
- اگر BackPack+ ری‌استارت شود، وضعیت را از خود رکورد آروان می‌خواند و بی‌دلیل جابه‌جا نمی‌کند.
- در درخواستی که به آروان فرستاده می‌شود **فقط آی‌پی** عوض می‌شود. TTL، حالت CDN و بقیهٔ تنظیمات رکورد همان قبلی می‌ماند.

## راه‌اندازی

### ۱) روی هر سرور ایران: `iran-setup.sh`

این اسکریپت کارهای لازم روی سرور ایران را خودش انجام می‌دهد:
- تانل‌هایی که از سرور خارجِ تو وصل‌اند را پیدا می‌کند. فایل `/etc/backpack/*.toml` را می‌خواند و می‌بیند هر تانل از چه آی‌پی‌ای وصل است.
- به هر کدام یک پورت چک جدا اضافه می‌کند (`59999`، `59997`، `59995`، …)، فقط پورت‌هایی که آزادند.
- اگر ufw یا firewalld فعال باشد، پورت را **فقط برای آی‌پی سرور خارج** باز می‌کند.
- در آخر خطی را چاپ می‌کند که در ویزارد سرور خارج لازم داری، مثلاً `59999:main,59997:panel`.

```bash
# روی سرور خارج بعد از نصب BackPack+ یک نسخه در /etc/backpack-plus/iran-setup.sh هست:
scp /etc/backpack-plus/iran-setup.sh root@IRAN_SERVER:
ssh -t root@IRAN_SERVER bash iran-setup.sh            # تعاملی
# یا: bash iran-setup.sh --kharej <IP خارج> --yes
```

**ایمنی روی سیستم زنده:**
- قبل از هر تغییری برنامه را نشان می‌دهد و تأیید می‌گیرد. با `--dry-run` فقط نشان می‌دهد و هیچ تغییری نمی‌دهد.
- از هر فایل بکاپ می‌گیرد (`/etc/backpack/backpack-plus-backups/`).
- فایل جدید را قبل از جایگزینی با `backpack check -c` خودِ BackPack اعتبارسنجی می‌کند و چک می‌کند که **دقیقاً یک خط** اضافه شده باشد و چیز دیگری عوض نشده باشد.
- تانل‌ها را **یکی‌یکی** تغییر می‌دهد. BackPack تغییر را خودش می‌بیند و همان یک تانل را ری‌لود می‌کند: اتصال‌های آن تانل **حدود ۲ ثانیه** قطع می‌شوند و بقیهٔ تانل‌ها دست نمی‌خورند.
- بعد از ری‌لود چک می‌کند همهٔ پورت‌های قبلی تانل دوباره باز شده باشند. اگر نه، **بکاپ را خودکار برمی‌گرداند** و متوقف می‌شود.
- اگر BackPack+ روی خارج در حال اجرا باشد، مسیر را سرتاسری هم تست می‌کند و می‌گوید «end to end OK».
- `--remove` همه را دقیقاً به حالت قبل برمی‌گرداند.

> اگر بعداً از منوی BackPack لیست Forwarded Ports را دستی عوض کردی، خط `…=127.0.0.1:59998` را نگه دار. اگر پاک شد، `iran-setup.sh` را دوباره اجرا کن.

### ۲) آروان و تلگرام

- در پنل آروان یک **کلید API** با دسترسی DNS بساز.
- **TTL** رکورد را کم بگذار، مثلاً ۱۲۰ ثانیه.
- یک ربات **جدید** از `@BotFather` بساز و آیدی عددی‌ات را از `@userinfobot` بگیر. از ربات خود BackPack استفاده نکن: دو برنامه نمی‌توانند هم‌زمان پیام‌های یک ربات را بخوانند.

### ۳) روی سرور خارج: نصب و ویزارد

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/MHBehzadian/BackPack-/main/install.sh)
```

اسکریپت باینری و سرویس را نصب می‌کند و بعد **ویزارد** را اجرا می‌کند. ویزارد این‌ها را می‌پرسد:
- سرورهای ایران: اسم، آی‌پی، و پورت‌های چکی که `iran-setup.sh` چاپ کرد؛
- **کدام سرور مبنا باشد**؛
- کلید و دامنهٔ آروان. همان لحظه رکورد را از آروان می‌خواند و نشان می‌دهد الان روی کدام سرور است.
- توکن ربات و آیدی‌ات. همان لحظه یک پیام آزمایشی می‌فرستد.
- زمان برگشت به سرور مبنا (پیش‌فرض ۱۰ دقیقه).

بعد `backpack-plus check` را اجرا می‌کند که آروان، تک‌تک تانل‌ها، DNSها و ربات را تست می‌کند. اگر همه درست بود، می‌پرسد سرویس را روشن کند یا نه.

- **ویرایش بعدی:** `backpack-plus setup`. هر سؤال مقدار فعلی را نشان می‌دهد و با Enter همان می‌ماند.
- **لاگ‌ها:** `journalctl -u backpack-plus -f`
- **اجرای دوبارهٔ اسکریپت نصب**، باینری را آپدیت می‌کند. اگر نسخهٔ جدید کانفیگ فعلی را قبول نکند، هیچ چیزی عوض نمی‌شود.

> تا وقتی این کد در برانچ `main` نیست، قبل از دستور نصب `BPP_REF=claude/optimistic-franklin-2k8khl` را بگذار. چون هنوز release نساخته‌ایم، روی سرور Go 1.22+ لازم است تا از سورس ساخته شود.

### پیام‌ها (نمونه، از تست واقعی)

```text
🚀 BackPack+ شروع به کار کرد — الان پشت دامین: iran1 — سرور مبنا: iran1 — ترتیب: iran1 (2 تانل)، بعد iran2 (2 تانل)
🔴 تانل سرور iran1 (فعال، پشت دامین) قطع است. علت: main: dial tcp …:59999: connect: connection refused
🔁 رکورد دامین عوض شد — سرور iran1 قطع شد — tun.example.com از iran1 به iran2
✅ iran2 حالا پشت دامین است — همهٔ DNSها آی‌پی جدید را برمی‌گردانند (بعد از 27 ثانیه)
🟢 تانل سرور iran1 (رزرو) دوباره وصل شد — اگر 10 دقیقه بدون قطعی بماند، رکورد را به آن برمی‌گردانم.
🔁 رکورد دامین عوض شد — iran1 (سرور مبنا) 10 دقیقه بدون قطعی پایدار بوده؛ برگشت به آن
🟠 تانل سرور iran1 (فعال، پشت دامین) ناپایدار است: 3 قطعی در 5 دقیقه اخیر.
🚨 سرور فعال iran1 قطع است و هیچ سرور سالم دیگری برای جابه‌جایی وجود ندارد.
```

### دستورها

| دستور | کار |
|---|---|
| `/status` | وضعیت هر سرور و **هر تانل** (سالم/قطع، RTT)، سرور مبنا ⭐️، و اینکه الان کدام سرور پشت دامین است 👉 |
| `/primary iran2` | عوض کردن سرور مبنا. اگر سالم باشد رکورد همان لحظه به آن می‌رود. اگر نه، وقتی ۱۰ دقیقه پایدار ماند. این انتخاب بعد از ری‌استارت هم می‌ماند. اگر بعداً `primary` را در فایل کانفیگ عوض کنی، مقدار فایل برنده است. |
| `/switch iran2` | انتقال دستی رکورد. تا `/release` برگشت خودکار به سرور مبنا متوقف می‌شود، ولی اگر همین سرور قطع شود باز خودکار جابه‌جا می‌کند. برای سرور ناسالم: `/switch iran2 force` |
| `/release` | آزاد کردن سوییچ دستی |
| `/auto off` / `/auto on` | خاموش/روشن کردن جابه‌جایی خودکار. در حالت خاموش فقط هشدار می‌دهد و دستور مناسب را پیشنهاد می‌کند. |

فقط chat_idهای داخل کانفیگ می‌توانند دستور بدهند.

ویزارد این فایل را کامل می‌نویسد. نمونه: [`config.example.json`](config.example.json).

| کلید | پیش‌فرض | توضیح |
|---|---|---|
| `primary` | سرور اول | سرور مبنا |

| `dns_verify.resolvers` / `timeout` | گوگل، کلادفلر، Quad9 / `20m` | DNSهایی که بعد از تغییر رکورد پرسیده می‌شوند |
| `telegram.bot_token` / `chat_ids` / `label` | — | ربات، آیدی‌ها، و برچسب اول هر پیام |

## تست‌ها

همه‌چیز روی **BackPack واقعی (v1.8.5) با تانل‌های TCP Mux واقعی** تست شده است. سه سرور (دو ایران و یک خارج) در network namespaceهای جدا راه‌اندازی شدند، هر سرور ایران با دو تانل. آروان و تلگرام شبیه‌سازی شدند، و DNS با ۱۵ و ۲۵ ثانیه تأخیر انتشار.

| سناریو | نتیجه |
|---|---|
| `iran-setup.sh`: dry-run، اجرای تعاملی و `--yes`، قطعی هر تانل هنگام اعمال (~۲ ثانیه، یکی‌یکی) | ✅ |
| قطع یک تانل از دو تانلِ سرور مبنا ← تغییر رکورد در ۸ ثانیه ← تأیید انتشار DNS ← کاربر از ایران ۲ | ✅ |
| برگشت سرور مبنا ← نه زودتر از زمان تعیین‌شده ← برگشت رکورد | ✅ |
| ناپایداری (۳ قطعی ۴ ثانیه‌ای کل سرور) ← «ناپایدار» ← جابه‌جایی | ✅ |
| `/status`، `/primary`، `/switch`، `/release` | ✅ |
| آروان از دسترس خارج هنگام جابه‌جایی ← یک بار گزارش، تلاش دوباره، موفقیت بعد از برگشت آروان | ✅ |
| هر دو سرور قطع ← رکورد دست نمی‌خورد ← اولین سروری که برگشت | ✅ |
| ری‌استارت BackPack+ وسط فِیل‌اوور ← خواندن وضعیت از رکورد، بدون جابه‌جایی بی‌دلیل | ✅ |
| `iran-setup.sh --remove` ← فایل‌ها بایت‌به‌بایت مثل قبل | ✅ |
| تانلی که ری‌لود نمی‌شود ← بازگردانی خودکار بکاپ | ✅ |
| رد شدن فایل توسط `backpack check` ← هیچ تغییری | ✅ |
| ufw فعال ← قانون فقط برای آی‌پی خارج | ✅ |

تست‌های خودکار: `go test ./...` و `bash tests/iran-setup-test.sh`. شکل‌های مختلف فایل TOML، مثل لیست تک‌خطی، کامنت و جدول `[client]`، هم تست شده‌اند.

## محدودیت‌ها

- BackPack+ مسیر **خارج ← ایران** را می‌سنجد. اگر سرور ایران فقط برای کاربرهای داخل ایران در دسترس نباشد ولی از خارج وصل باشد، این را نمی‌بیند. ایدهٔ بعدی: چک از داخل ایران با نودهای ایرانی check-host.net.
- کاربرانی که آی‌پی قبلی را کش کرده‌اند تا پایان TTL به سرور قبلی می‌روند.
- عملکرد API آروان با یک شبیه‌ساز تست شده است، نه با حساب واقعی. `backpack-plus check` فقط رکورد را می‌خواند. اولین جابه‌جایی واقعی را یک بار دستی با `/switch` امتحان کن.

## English summary

BackPack+ runs on the **kharej** server next to the BackPack client tunnels to two (or more) Iran servers. Every tunnel gets its own probe port on its Iran server, mapped back through that same tunnel to BackPack+'s echo server (`127.0.0.1:59998`). The check is therefore end to end, per tunnel.

- The **primary** server (`"primary"`, chosen in the wizard, changeable with `/primary`) normally holds the domain.
- When the server the domain points at is down or unstable, the ArvanCloud A record moves to a healthy server. Only the IP changes; TTL, CDN flag and the other record settings are kept. Resolvers are then polled until the new IP has propagated.
- The record returns to the primary after it has been clean for `failback_after` (10 min).
- By default, any failed tunnel makes its server unhealthy (`require_all_tunnels`).
- `iran-setup.sh` (Iran side) finds the tunnels connected from the kharej server and adds one probe port to each, one tunnel at a time. Each file is backed up and validated with `backpack check -c`. Each tunnel reloads (about a 2 s drop) and must come back with all its ports, or the backup is restored. It opens ufw/firewalld for the kharej IP only. `--remove` undoes all of it.
- `install.sh` (kharej side) installs the binary, runs the `backpack-plus setup` wizard (it tests Arvan and Telegram live) and `backpack-plus check`, then asks before enabling the service.
- Telegram commands: `/status`, `/primary`, `/switch`, `/release`, `/auto`.
